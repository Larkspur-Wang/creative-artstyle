# Generation Failure Recovery

不要在同一个失败 prompt 上反复改形容词烧配额。先分类，再降级。

## 失败类型与下一步

| 类型 | 信号 | 下一步 |
|---|---|---|
| policy | policy / sensitive / 版权 / copyright / 正脸 IP | 降低 IP 识别度，改无正脸/背影/侧袖表达，或换模型（Seedance→Kling）。只重试一次。 |
| timeout | timeout / 超时 / 504 | 任务可能仍在跑。查原任务 id，稍后重试，不重复扣费重开。 |
| channel | channel / 渠道 / not available / 不可用 | 模型通道暂时不可用。等待恢复或切换到备用模型。 |
| download | 生成成功但结果没取回 / 下载失败 | 结果已生成，保留 prompt 与首帧，重新拉取一次通常能拿到。 |
| continuity | 多段视频场景/角色漂移 | 顺序生成 + 每段共用稳定角色/场景/道具参考图，不并行纯文生直接拼。 |
| composition | 多人动作崩坏 / 像素小人融化 | 拆镜、减少活跃角色、参考图锁位或后期，不靠加长 prompt 硬顶。 |

## 硬规则

- 被审核拦截：只重试一次，第二次仍失败就换模型或换表达，不反复改词。
- 超时/下载失败：区别于审核失败，明确告诉用户"内容没问题，是通道/回传问题"。
- 多段连续故事：禁止把多条独立纯文生结果直接 ffmpeg 拼合当"完整连续视频"。
- 同类结构错误连续两次：停止堆 prompt，改用参考图/分段/降级方案。

## UI 表达

失败卡要"诚实地好看"：显示失败类型标签 + 一句原因 + 一个下一步动作，而不是一个模糊的红点或"处理中"。
