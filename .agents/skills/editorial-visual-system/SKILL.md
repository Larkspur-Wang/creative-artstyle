# Editorial Visual System

把界面做成有编辑感、可识别、能持续扩展的视觉系统，高级感来自信息取舍和秩序，不来自装饰堆叠。

## 9 条原则

1. 先保证可读，再谈高级感：每个视图/每张卡只回答一个问题（现在到哪步、出了什么问题、下一步做什么）。
2. 用"杂志编辑部"而不是"后台面板"的气质。避免紫蓝渐变、玻璃拟态、满屏圆角、无意义阴影。
3. 每类状态/每个能力有自己的视觉语法，不是换个文字：待处理留白、生成中进度线、审核突出预览、失败用警示色+原因。
4. 把产出物当主角，操作信息放外围。预览不能被徽章、按钮、元信息挤成缩略图。
5. 强约束的视觉变化：固定卡片骨架/比例/内边距/信息位置，只变封面、强调色、纹理、局部构图（style lock）。
6. 受控印刷感：套色错位、半调网点、纸张颗粒只出现在背景/分割线/装饰，不覆盖文字和状态。颗粒是材质不是滤镜。
7. 明确的色彩角色，不是"好看的颜色集合"。
8. 高级感交给字体、比例、留白：标题不要全加粗，用字号/字距/行高/留白制造层次；数字状态用等宽辅助字体。
9. 错误"诚实地好看"：文案超长、比例不符、发布失败都直接展示原因，不用模糊的"处理中"掩盖。

## 色彩角色（限制到 5 类）

| 角色 | 职责 |
|---|---|
| 纸张底 | 大面积背景 |
| 墨黑 | 正文、标题 |
| 辅助冷色 | 分割线、面板、灰阶 |
| 品牌强调色 | 只承担"当前上下文 / 需要注意 / 需要操作" |
| 风险色 | 只承担错误与失败 |

强调色不与风险色混用；不同时用多种高饱和色争夺注意力。

## 参考库 ≠ 当前方向

- 参考库（只读，比较材质/构图/色彩）与当前采用的产出示例分开存放。
- 不要把整个参考库渲染进产品界面。

## 推荐编辑部方向

Minimalist（克制结构）/ Three-Color Hardcut（限定色+硬切）/ Grainy Print（受控颗粒）/ Blue-Black Print（蓝黑墨+奶纸）。
